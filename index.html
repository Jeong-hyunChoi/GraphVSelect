Code

GraphVSelect is a training-free zero-shot REC framework: verify the evidence first, then compare all candidates under the same verified relational context.

Abstract

Referring Expression Comprehension localizes an image region described by natural language. Existing zero-shot approaches typically rely on proposal matching or independent box-wise verification, providing limited explicit comparison among candidates. Recent scene graph-based methods introduce structured relational evidence, but construct the graph in a single pass, making subsequent reasoning sensitive to inaccurate objects. We present GraphVSelect, a training-free framework for reliable zero-shot REC through verified graph-guided selection. Our method hierarchically verifies candidates before constructing a query-conditioned scene graph. It then jointly ranks all candidates under the verified relational context and selectively re-examines ambiguous predictions using the top-1/top-2 likelihood margin. Across RefCOCO/+/g and the challenging Ref-L4 with multiple vision-language models, GraphVSelect improves over the strongest zero-shot baseline by a relative 15.0% and 16.6%, respectively, with the largest gains on long, compositionally complex expressions.

Method

Given an image and a referring expression, GraphVSelect localizes the described object with two stages, both built on frozen off-the-shelf models and requiring no REC-specific training. Hierarchically Verified Scene Graph Construction verifies and repairs object proposals and their descriptions before assembling a query-conditioned scene graph. Confidence-Aware Structured Selection then scores all candidates jointly under this graph and re-answers only the ambiguous cases.

Hierarchically Verified Scene Graph Construction

Prior graph-based REC builds the scene graph in a single generation pass and treats it as fixed evidence, so a spurious box or an under-informative caption silently becomes part of the reasoning context. We instead treat construction as verify-and-repair.

Object-level verification. An open-vocabulary detector proposes query-relevant regions. Each proposal is marked in the full image and a frozen VLM is asked whether it depicts the object concept; low-confidence proposals are removed, and if a query-relevant category ends up unrepresented the detector is re-queried and only verified regions are added back. The same signal prunes false positives and drives targeted re-detection.

Caption-level verification. A caption produced from the crop alone often omits what separates an object from its same-category siblings. For each verified object we generate an initial caption and five alternatives conditioned on the crop and a spatial descriptor, score them with two listener prompts, and keep the most visually grounded and discriminative one. Verified nodes are joined with query-relevant pairwise relations and a global caption into a scene graph serialized as id-indexed JSON.

Confidence-Aware Structured Selection

Box-wise verification asks an independent True/False question per candidate. Set-level predicates such as "middle" or "closest" are undefined for a single isolated region, and independent bounded confidences saturate, leaving several candidates equally "true". We instead score all candidates within a single query over the shared graph.

List-wise constrained scoring. Every candidate of the target category is marked with its id on one image. The VLM receives the marked image, the query and the serialized graph, and the answer is constrained to the valid id tokens so that each candidate's first-token log-likelihood yields a full ranking with no unparseable outputs.

Confidence gate and re-answering. The top-1/top-2 log-likelihood margin measures ambiguity. A threshold is set to the 30% quantile of margins on an unlabeled calibration set, so no ground truth is needed. Confident cases keep the top-1 answer; low-margin cases are re-asked between the top two candidates in both presentation orders, and the summed log-likelihoods cancel the answer-slot bias exactly. On average this costs 1.53 VLM calls per expression.

Results

GraphVSelect is evaluated on RefCOCO, RefCOCO+ and RefCOCOg and on the more challenging Ref-L4, on all official splits and without any task-specific training. Qwen3-VL-8B-Instruct is the default backbone; LLaVA-OneVision-7B and Molmo-7B-D are also evaluated to assess generalization across backbones. All numbers come from a single deterministic run.

GraphVSelect achieves the best result on every RefCOCO/+/g split, with an average accuracy of 74.89, outperforming the strongest baseline by 9.8 points. On Ref-L4 it improves mAcc by 8.59 points over SGREC and 10.39 over GroundingAgent, and the gain persists under the strictest threshold: +10.04 points at Acc0.9 over the strongest baseline, indicating more precise localization rather than merely identifying the object.

Qualitative Comparison

Both baselines are distracted by the nearby bench instead of the bronze boar, select a different dog despite the distinctive attributes in the query, and localize incorrect or over-sized regions for the bag of peppers. GraphVSelect resolves these contextual and same-category ambiguities and produces boxes closely aligned with the ground truth.

Object-level verification alone gives consistent gains on every dataset, up to 7.3 points on RefCOCO/+/g and 6.7 on Ref-L4 for the weaker backbones. Without the graph, structured selection performs poorly: list-wise comparison depends on relational evidence. With it, the full setting improves by 9.6 to 28.1 points on RefCOCO/+/g and 15.0 to 31.7 points on Ref-L4. Adding the same graph to box-wise verification yields mixed results for the stronger backbones, so scene graph evidence is exploited most consistently when it is shared across candidates during joint selection rather than supplied to separate binary decisions.

What Each Mechanism Fixes

Candidate augmentation recovers targets missed by the initial detector. Caption rewriting produces discriminative descriptions for similar candidates. Confidence-aware re-answering revisits ambiguous initial predictions. List-wise selection compares all candidates under a shared graph context, resolving cases in which independent box-wise verification picks the wrong object.

Failure Cases and Limitations

Among all 9,111 incorrect predictions on Ref-L4 test, 49.6% are detection misses, where the target never enters the candidate set, and 50.4% are selection errors, where the correct candidate is available but another one is chosen. GraphVSelect therefore depends on proposal recall and on the relational reasoning ability of the VLM, and since the prediction is selected directly from the candidate set without box refinement, inaccurate proposals also limit localization quality. Some remaining low-IoU predictions arise from ambiguous expressions for which the benchmark provides only one annotated box.
